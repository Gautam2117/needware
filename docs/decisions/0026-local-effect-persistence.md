# Durable local effect execution

Local applications use the same trusted-shell clipboard review as encrypted applications. A bounded private effect record persists in SQLite or IndexedDB before dispatch authorization, after the returned outcome, and before native callback completion. Every transition uses the current application generation; rejected writes preserve native state and pending intents. Cold restoration requires the exact signed package, local application scope and state cut. Stale results remain available for explicit review and export.

Revision activation and history rollback retain the current effect ledger. Historical prepared, dispatched, completed or cancelled records never replace it. Cancelling or consuming an intent therefore cannot be undone by restoring a historical application snapshot. Unknown external outcomes cannot be executed again. A fresh trusted-shell click is required for clipboard execution; unrecorded returned results guard replacement, deletion and page exit.

SQLite adds the nullable effect column to both application and history tables in one transaction. A failure on the second ALTER rolls back the first without changing existing data or history. A previously selected OPFS backend never silently falls back when opening fails. New installations without OPFS use the existing explicit IndexedDB backend.
