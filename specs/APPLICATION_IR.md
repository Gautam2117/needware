# Application IR — technical schema 1

Rust `needware-ir` is canonical. `application.schema.json` and the TypeScript package are generated by `cargo run -p xtask -- contracts`. Consumers must not hand-edit generated contracts.

Applications identify themselves and each logical revision with UUIDs. Package identity is computed separately. Values are tagged; integer coefficients use canonical signed base-10 strings, preventing JavaScript precision loss. Decimals retain an explicit scale. Types, UI kinds, styles, expressions, actions and migrations are closed tagged unions; unknown fields fail parsing.

Persistent state contains revision, named values and collections of UUID-addressed records. Runtime state cannot introduce unknown collections or fields. Required fields, value types and configured bounds are validated before transaction commit.

Expressions read explicit state/event/item/context values. Arithmetic checks signed 64-bit overflow and division by zero. Evaluation has depth/fuel limits. Models cannot insert scripts, HTML, SQL, dynamic functions or imports.

Each runtime event has one expression budget of 1,000,000 evaluated nodes, shared by all action fields, nested sequences, selected conditional branches and parallel groups. Conditions consume this budget too; unselected branches do not execute. Action count (256), action nesting (32) and prepared effects (four) have independent event-wide bounds. Local mutations and effect preparation in parallel groups run in definition order; host execution of approved effects may be concurrent. Exhaustion returns the typed `RuntimeError::Limit`, discards prepared effects and leaves state and navigation unchanged. Each later event receives a fresh budget. Rendering uses its own bounded budget.

Expression evaluation also shares a 32 MiB materialization allowance: owned strings, cloned value-list storage, conservative map-entry overhead and sorting buffers are charged before allocation. This is deterministic resource accounting, not a measured process-RSS limit. Generated text is limited to 64 KiB with checked serialization, including escaping. Stable merge sorting charges fuel for merge steps and string comparison work and stops immediately on exhaustion. Numeric keys sort numerically; UTC instants compare independently of their textual timezone offsets. Missing keys, heterogeneous types and incompatible decimal scales reject rather than sorting through string coercion.

IR and event JSON decoding is limited to 2 MiB. Durable state has a separate 16 MiB strict JSON boundary, followed by application-schema validation. Duplicate members, unsupported numeric encodings, trailing input and unknown fields remain invalid. Restoring invalid state leaves the active state unchanged.

Static inference checks literal/state/collection types, boolean conditions, integer arithmetic, branch compatibility, collection predicates, sortable keys and action assignments. Item context follows list/table children and explicit expression iteration; create actions cannot read an existing record. Inferred non-null legacy state types are checked after every event and on restore.

The required `typed_contracts_v1` feature enables `state_schema` and `event_schema`. State contracts cover exactly all state-default keys; event contracts cover exactly all action names, including an empty contract for actions without external inputs. Each contract field has a declared `DataType` and supported constraints. Defaults and derived expressions are forbidden in contracts, including nested record fields. State defaults remain in `state`; null requires an optional type and empty containers retain their declared element types. Constraints reject invalid bounds at package acceptance.

Event expressions are inferred against the enclosing action's contract throughout nested sequences, conditionals and collection operations. Unknown keys and event reads outside action/test context reject. Dispatch rejects missing required inputs, unknown keys, wrong types and invalid constraints before preparing any changes or effects. Omitted optional inputs become null. Behavior-test inputs are checked against the same contracts. The renderer receives each action's input keys from Rust and scopes outgoing form inputs accordingly; Rust independently validates incoming events.

Legacy technical-schema-1 packages omit the new empty maps and keep their original serialized content identity. Legacy undeclared events retain inferred/unknown behavior with bounded runtime validation. New authored browser examples and compiler guidance use explicit contracts. Older runtimes reject the required feature. Decimal arithmetic and derived-field materialization remain unsupported execution features.

Migration operations are bounded to 256 per transition and 32 source declarations per package. Native migration preview has one shared work budget, rejects event/ambient reads, reads a stable snapshot for each transform and validates the resulting state against the target schema. Removal and transform operations require destructive consent. Exact source-state review and atomic persistence precede activation; see the revision ADR and CLI documentation.

The schema currently describes more component/action families than the executed browser surface. The project status records this gap; schema representation alone is not feature completion. Derived-field materialization, all component behaviors and synchronized schema epochs remain under implementation.
